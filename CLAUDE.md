# CLAUDE.md — comit

Guidance for AI agents working in this repository. Judgment calls only; the deterministic
rules that belong in hooks are listed at the bottom as *unwired*, not restated as prose.

## What this repo is

**COMIT** — Cost Optimisation Model for Industrial Technologies. An R package (v1.4.0) with
a golem/Shiny front end, solving a least-cost industrial decarbonisation pathway as an LP
(MILP when a minimum hydrogen plant size is set) via `ROI`/`highs`.

Two distinct bodies of work live here and they must not be confused:

| | The running model | The CaRB3 redesign |
|---|---|---|
| Where | `R/` (64 files, ~18k lines), `tests/testthat/` (25 files), `app.R` | `docs/specs/`, `docs/notes/` |
| What it is | Working code, solves today, national/cluster-coupled | **Documentation only.** A spec for a future per-site implementation. Nothing is built |
| Language | R | Deliberately language-agnostic (R or Python) |
| Inputs | `data_template_archive/comit_input_1_4_0_public_updated.xlsx`, 66 sheets | Entities described in the spec |

**A spec change is not a code change.** `docs/specs/` describes a system that does not
exist yet. Do not "implement" it into `R/` unless asked explicitly.

## Generated files — never hand-edit

Four generators live in `docs/notes/examples/`. Editing their output is always wrong; edit
the source and regenerate.

| Output | Generated by | Source | Has `--check`? |
|---|---|---|---|
| `docs/specs/interfaces/*.md` | `build_interface_docs.py` | implementation spec §3 and §8 | **yes** |
| `docs/specs/diagrams/*` | `build_spec_flow_diagram.py` | the implementation spec | **no** |
| `docs/notes/data/emissions_source_classification.csv` | `build_emissions_classification.R` | the input workbook | no |
| `docs/notes/data/comit_sector_processes.{csv,json}` | `build_comit_process_taxonomy.R` | the input workbook | no |

Both Python generators have the spec's structure compiled into them as literals — exact
heading strings, section prefixes, and the label ranges `A1-A9 / C1-C9 / V1-V17 / D1-D11`.
**Renumbering a section or adding a `C10` or `V18` requires a Python edit, not just a
markdown edit**, and `build_interface_docs.py` raises `ValueError` rather than degrading.

Python here is stdlib-only by necessity: **`pandas` is not installed.** Write validators
and tools in stdlib Python or R.

## Label families — check before you introduce one

Seven families are in use, and two documents legitimately use the same letter for different
things:

| Family | Means | Defined in |
|---|---|---|
| `D1`–`D11` | Design decisions | **vision doc §6** — not the implementation spec |
| `C1`–`C9` | Constraints | implementation spec §5.5 |
| `V1`–`V17` | Validation tests | implementation spec §10.3 |
| `A1`–`A9` | Algorithms | implementation spec §4 |
| `S1`–`S9` | Pipeline stages | implementation spec §2.1 |
| `R1`–`R3` | Profile rules | implementation spec §3.3.3 |
| `G1`–`G3` | Scale gates | implementation spec §9.2 |
| `PD1`–`PD3` | v2 plan decisions | v2 overview doc |

**This repo has been bitten by collisions three times.** Pipeline stages were once numbered
`C` alongside the constraints and had to be renamed `S`. The vision doc still uses `λ` for
the stranding factor, which is `ξ` — `λ` is the §5.6 peak factor. And the v2 plan initially
reused `D1`–`D3`, colliding with the vision's own decisions in documents citing both.

Before introducing any new label **or distinguishing adjective**, grep for it. When a
collision is unavoidable, the house pattern is rename plus a short disambiguation note, as
at implementation spec §6 lines 2126–2127.

## Things that have gone wrong here

- **Count before writing a count.** Hardcoded counts in prose go stale silently. The
  implementation spec asserts "Eighteen entities" at §3; the v2 plan shipped "nineteen
  items" for a list of twenty-three. Run `grep -cE` on the item pattern first.
- **Open cited `R/…:line` references; do not trust the prose around them.** Two spec
  citations described behaviour the code does not have — the retrofit `int` multiplier uses
  the retrofit's own lifetime rather than the host's residual, and
  `fct_constraints_tech_stability.R` is disabled and has a different form. There are ~25
  such citations and nothing verifies them.
- **A legacy-equivalence claim must enumerate every condition.** "This reproduces COMIT
  when X" appeared in five places listing one of three conditions. The missed one was that
  COMIT pins capacity with an equality (`fct_constraints_capacity_transfer.R:364-365`)
  while the new constraint only bounds it.
- **Read the file that actually bites.** `fct_constraints_existing_capacity.R` carries a
  comment saying it is not in use; the same decay is applied unconditionally inside
  `fct_constraints_capacity_transfer.R`. Comparing against the wrong one wastes a day.

## Data caveats worth knowing before quoting a number

- `docs/notes/data/` is **derived reference data. COMIT never reads it.**
- The public workbook's `commodities` and `Fuel_emissions` sheets are labelled *dummy
  figures*. The classification and method are real; the absolute intensities are not.
- Seven files under `docs/notes/data/` were built by hand research with no committed
  validator. Their key integrity is currently perfect and nothing would tell you if that
  changed.
- `R/fct_emissions.R` hardcodes the indirect-commodity list (`:180-183`) and the biomass
  category string (`:234`), so the carrier taxonomy is not fully data-driven.

## Conventions

- Units: energy/capacity **PJ** (GW for CHP), emissions **kt/Mt CO₂e**, cost **£m**,
  distance **km**, prices based to **2021**.
- Notes are `docs/notes/NN_snake_case.md`, sequential, never reused.
- Specs are `docs/specs/YYYY-MM-DD-kebab-slug.md`.
- **Every new document gets a row in `docs/notes/README.md`.** It is the only index and it
  is maintained by hand. An unregistered document is invisible.
- Superseded documents are not deleted; they keep their row with a `⚠️ **Superseded**`
  prefix.
- Every `##` section of the implementation spec carries a `*Section last updated: …*` line.
  It is load-bearing for the interface generator and must round-trip: edit the section,
  bump the date, regenerate.
